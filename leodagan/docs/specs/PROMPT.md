## Validation et traçabilité

Crée et exécute les tests de comportement, d'intégration réelle des chemins critiques, de sécurité/refus, de Docker et de recette locale définis dans `SPECIFICATIONS_TECHNIQUES.md`. Vérifie réellement, dans la mesure permise par l'environnement, le fonctionnement sous Docker Desktop macOS : image, Compose, volume natif, SQLite, gateway, modèle, Slack, Telegram, santé, redémarrage et restauration. Si le socket Docker ou les permissions de l'API LinkedIn sont indisponibles, consigne l'essai, le message d'échec et la vérification manuelle restante ; ne marque pas ces tests comme réussis.

Ne mets pas en service l'ancien cron ni un nouveau job périodique. Avant d'activer le service conversationnel, contrôle les allowlists, les scopes, l'absence d'outil de publication, la persistance, la sauvegarde/restauration et le refus depuis une autre identité. Un résultat de test seulement simulé ne remplace pas la recette réelle demandée. Les actions destructrices sur l'ancien runtime, les volumes ou les déploiements exigent l'étape de validation déjà décrite.

Termine par un bilan factuel : fonctionnalités effectivement livrées, table de traçabilité, commandes de test exécutées et résultats, limites exactes, éléments non vérifiés, étapes manuelles restantes et état du service.
