# Politique opérationnelle — Père Blaise

**Autonome :** inventorier les seuls fichiers réguliers visibles de `Downloads`, proposer un plan, rechercher par nom sous `Documents`, notifier une analyse hebdomadaire une fois activée. Aucune de ces opérations ne déplace de fichier. F-013/F-014 sont reportées : aucune collecte, inférence, consultation ni utilisation des apprentissages. Les anciennes données et backups demeurent intacts ; la mémoire Hermes générale reste désactivée.

**Validé par une commande de l'auteur :** `range <ID>` est l'accord final pour le plan exact de 30 minutes. `envoie` est l'accord explicite pour envoyer un fichier par l'API du canal d'origine ; plusieurs résultats exigent un choix non ambigu.

**Dépôt sur ordre du seul propriétaire :** sur Slack, `tiens` avec exactement un fichier joint ; sur Telegram, un document avec la légende `tiens`, ou le message `tiens` suivi d'un seul document dans les cinq minutes. Cet ordre autorise le broker à créer un nouveau fichier à la racine de `Downloads`. La préparation Telegram est liée au chat privé du propriétaire, à usage unique et perdue au redémarrage ; un document spontané est refusé. L'identité Telegram/Slack de Clément est vérifiée par ID immuable privé et allowlist avant téléchargement. Aucun écrasement, chemin libre, exécution, décompression sur disque, envoi au modèle ni déclenchement de classement. Taille bornée et formats autorisés contrôlés sur le contenu ; un nom et une extension ne suffisent pas. Un échec retire le fichier temporaire. Le propriétaire examine les fichiers déposés avant de les ouvrir ; les contrôles de format ne prouvent pas l'absence de logiciel malveillant dans un document valide.

**Interdit :** lire le contenu par le modèle, lui fournir hash ou nom de document déjà classé, déplacer sans `range`, modifier/supprimer un document préexistant, créer un dossier autre que `a_trier`, écraser une cible, envoyer à un autre canal ou DM Slack, partager runtime/secrets entre agents, purger automatiquement les backups. Les fichiers cachés, symlinks et objets non réguliers sont exclus ; un inventaire inaccessible ou trop grand échoue en bloc.

**Incident :** la transaction conserve ses backups et son journal. Un échec entraîne rollback limité aux artefacts du plan ; si une édition concurrente empêche un retour sûr, état `BLOCKED_RECOVERY`, arrêt des nouveaux `range`, intervention de l'exploitant. Un timeout d'API de livraison est incertain et ne doit pas déclencher de répétition automatique. Les IDs d'événements entrants sont enregistrés avant traitement dans le volume privé pour empêcher le rejeu après redémarrage ; une commande interrompue peut devoir être renvoyée par son auteur après vérification du canal. Les plans clos et IDs d'événements terminés sont conservés 30 jours avant purge de métadonnées ; les journaux techniques ne disposent pas encore d'une purge chronologique validée ; backups et données d'apprentissage préexistantes sans purge automatique.

Le modèle `openai-codex` utilise OAuth propre au volume Hermes. Aucun repli API ou fournisseur. Les exceptions et dates de revue figurent dans le README de l'agent.
